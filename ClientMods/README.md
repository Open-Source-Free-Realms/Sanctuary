# Client mods and game assets

Sanctuary's referee (GM) tools and a few housing features need small changes to the Free Realms
client UI, plus some data taken from the client. **Nothing from the game itself is stored in this
repository.** Everything below is either built from your own client install or copied from the
client's data, as described here.

## What lives outside this repository

| Asset | Where it comes from | Used for |
| --- | --- | --- |
| Free Realms client | The OSFR launcher (`%LOCALAPPDATA%/OSFRLauncher/Servers/<server>/Client`) | Playing, and the source of the stock UI movies the mods are built from |
| Asset server | `WebAPI:AssetUpstreamAddress` (default `http://osfr.editz.dev/assets`), or a local copy set in `WebAPI:AssetsDirectory` | The WebAPI proxies it to the client and adds the client mods to its manifest |
| Built client mods (`src/Resources/ClientMods/*.gfx`, `*.lst.z`) | Built locally with `build_client_mods.py` (git-ignored) | Referee Tools panel in the chat window, purple Referee Tools tree on the hub |
| `src/Resources/Names.json` | Generated by `extract_names.py` from the client's English locale | Item / NPC / house names in the referee panel's search |
| `src/Resources/FirstTimeEvents.txt`, `GameTutorialData.txt` | Copied from the client's data tables | Ids for `!fte` and `!tutorial` |

## Tools

- **Python 3** with **Pillow** (`pip install pillow`).
- **JPEXS Free Flash Decompiler** (`ffdec.jar`, https://github.com/jindrapetrik/jpexs-decompiler/releases).
- **Java** 8 or newer for ffdec (`--java`, defaults to the `java` on your PATH).

## Building the mods

The stock movies (`chatWindowCtrl.gfx`, `gamedock.gfx`, their `.lst` preload lists and the hub's tree
texture) are read straight from your client's `Assets_*.pack` files:

```
python build_client_mods.py --client "%LOCALAPPDATA%/OSFRLauncher/Servers/OSFR Public Server/Client" --ffdec path/to/ffdec.jar
```

With a local copy of the asset server (`<bucket>/<name>` folders), use `--assets <folder>` instead.
Both produce identical files.

The output goes to `src/Resources/ClientMods`. The WebAPI project copies that folder into its
output, serves the files, and patches them into the asset manifest it hands the client, so
**rebuild the WebAPI after building the mods**.

What gets built:

| Published file | Stock movie | Change |
| --- | --- | --- |
| `sanctuaryChatWindowCtrl.gfx` | `chatWindowCtrl.gfx` | `chatWindowCtrl/gm_panel.as` appended: the Referee Tools panel (lookups, world tools, NPC/prop editor, script and conversation authoring, the player conversation window) |
| `sanctuaryGameDock.gfx` | `gamedock.gfx` | `gamedock/gm_hub_button.as` appended, plus `gmTreeIcon`, a purple (hue-shifted) copy of the hub's tree icon |

Mods are published under new names because the client only downloads assets that are missing
from its local packs.

## Installing into a client

UI movies are loaded synchronously from the client's local packs, so they have to be installed
once per client (and again after each rebuild):

```
python install_client_mods.py --client "%LOCALAPPDATA%/OSFRLauncher/Servers/OSFR Public Server/Client"
```

This writes the built mods into a new `Assets_NNN.pack` (recorded in `sanctuary_client_mods.txt`)
and points `UI/UiModules/Main/wndChatLog.xml` and `wndGameDock.xml` at the renamed movies (the
originals are kept as `*.sanctuary-backup`). Close the client first.

Undo it with `--uninstall`.

The client must be launched against a Sanctuary WebAPI that serves the same build
(`AssetDelivery:IndirectServerAddress=http://127.0.0.1:20040/assets`, which is the default in
`appsettings.json`). Otherwise the client sees a manifest mismatch and can't load the chat window.

## Regenerating names

```
python extract_names.py --client "%LOCALAPPDATA%/OSFRLauncher/Servers/OSFR Public Server/Client"
```

## How the panel talks to the server

- Buttons send chat commands (`!gm`, `!npc`, `!prop`, `!house`, `!conv`, ...).
- The server answers with hidden system chat lines, `[[SANCTUARY_GM]]|kind|field|...`
  (`ChatHelper.SendGmPanelData`). The chat window mod swallows these and renders them.
- Free text in scripts, conversations and the player dialog is escaped as `\\` (backslash),
  `\n` (newline), `\p` (`|`), `\t` (tab) and `\s` for the spaces chat would otherwise trim or
  collapse (leading, trailing, or next to another space).
